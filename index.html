Best Practice 1: クラウド資産管理システムの自社構築

PythonとAWS APIを活用し、グループ内のマルチアカウント環境におけるクラウドリソースとリスクの統合管理を実現しました。

課題・背景 グループ内の各種ゲームサービス等が個別のAWSアカウントで運用されており、セキュリティ部門からクラウドリソースの現状把握や脆弱性の統合管理が不可能な「ブラックボックス化」状態でした。
技術的詳細
  • 開発言語: Python
  • 連携技術: AWS API (EC2, ECS, RDS等のリソースAPI, AWS Inspector API)
  • 各AWSアカウントからの権限移譲を受け、全リソース情報を一元的に収集・パースするバッチ処理ロジックを実装。
主な取り組み
  • AWS Inspector APIと連動し、特定の「CVEコード」を入力するだけで、全アカウントにまたがる脆弱性の影響範囲を瞬時に検索できる機能を開発。
  • IAMアカウント管理、ネットワーク設定、バックアップ状態などのコンプライアンス要件を自動でチェックし、違反項目を抽出する自動点検プロセスを確立。
成果と意義 従来は管理の死角となっていたクラウド環境に対する完全な可視性(Visibility)を獲得しました。新たな脆弱性(0-day等)の発表時にも、迅速に影響度を把握し、即座に是正措置を講じることが可能な体制を構築しました。

Best Practice 1: 클라우드 자산 관리 시스템 자사 구축

Python 및 AWS API를 활용하여, 그룹 내 멀티 계정 환경의 클라우드 리소스 및 리스크를 통합 관리하는 시스템을 구축했습니다.

도입 배경 그룹 내 다수의 게임 등 서비스가 개별적인 AWS 계정으로 운영되고 있어, 보안 부서 차원에서 리소스 현황을 파악하거나 중앙 집중적인 리스크(취약점) 관리가 불가능한 블랙박스 상태였습니다.
기술적 상세
  • 개발 언어: Python
  • 연동 기술: AWS API (EC2, ECS, RDS 등), AWS Inspector API
  • 서비스별 AWS 계정의 접근 권한을 할당받아, API를 통해 전체 클라우드 리소스 데이터를 일괄 수집하고 파싱하는 로직을 직접 구현했습니다.
주요 수행 내역
  • AWS Inspector API를 응용하여, 특정 CVE 코드 입력 시 전체 계정을 대상으로 취약점 영향도를 즉각적으로 스캔하고 파악하는 기능을 개발했습니다.
  • IAM 계정 관리, 네트워크 구성, 백업 상태 등 필수 보안 컴플라이언스를 스크립트로 자동 체크하여 위반 사항을 점검하는 프로세스를 반영했습니다.
성과 및 의의 기존 클라우드 환경의 가장 큰 문제였던 가시성(Visibility) 부재를 완벽히 해결했습니다. 이를 통해 신규 취약점 발생 시 즉각적인 영향도 파악은 물론, 체계적이고 선제적인 클라우드 보안 리스크 관리가 가능해졌습니다.

Best Practice 2: オフィスセキュリティ点検システムの開発

物理セキュリティ（クリアデスク等）点検のプロセスをシステム化・自動化し、手作業によるレポート作成の手間を大幅に削減しました。

課題・背景 オフィスでのPCや機密文書の放置を点検する際、従来は全座席を撮影し、手動で全画像をダウンロードしてファイル名を座席番号に変更し、レポートを作成するという非効率的なプロセスが存在しました。
主な取り組み
  • 自社で運用中のシステムに「オフィスセキュリティ点検モジュール」を新規追加設計および開発。
  • 建物の各フロアの座席表をベースに、全座席をボタン型のUIでマッピング。
  • 対象座席のボタンをクリックし、「Pass / 違反」を選択。違反時は即座に証拠写真をアップロードする直感的なインターフェースを実装。
自動化の実現 点検完了後、違反履歴（アップロードされた写真と座席情報の紐付け）をシステム上で直ちに確認できるようにし、違反項目と該当写真のファイル名が自動的にマッピングされた「点検結果レポート」の自動抽出機能を実装しました。
成果と意義 従来は2フロアの点検に2時間要していましたが、本システムの導入により9フロアを3時間で点検可能になりました。これにより点検作業時間を約67%削減し、業務効率を300%向上させるという圧倒的な成果を達成しました。

Best Practice 2: 오피스 보안 점검 시스템 자체 개발

물리적 보안(클리어 데스크 등) 점검 프로세스를 전면 시스템화하여, 수작업에 의존하던 점검 및 레포트 작성 시간을 혁신적으로 단축했습니다.

도입 배경 오피스 내 노트북, 기밀 문서 등의 방치 여부를 점검할 때, 기존에는 각 자리를 사진으로 촬영하고 일일이 다운로드하여 정해진 규칙으로 파일명을 변경한 뒤 수동으로 레포트를 작성하는 비효율적인 절차를 거쳐야 했습니다.
주요 수행 내역
  • 자체 구축 시스템 내에 '오피스 보안 점검 모듈'을 신규 기획 및 기능 추가.
  • 건물의 각 층별 자리표(도면)를 기반으로 모든 좌석을 버튼 형태의 직관적인 UI로 구현.
  • 점검 대상 자리의 버튼을 눌러 점검 항목에 대한 '통과/위반'을 판정하고, 위반 시 현장에서 즉시 증적 사진을 업로드하도록 로직 설계.
자동화 구현 점검 완료 시 시스템 이력을 통해 위반 좌석과 사진을 즉시 확인할 수 있으며, 서버에 저장된 위반 사진의 파일명이 위반 항목과 자동으로 매핑되어 기입된 '점검 레포트 자동 추출 기능'을 완성했습니다.
성과 및 의의 기존 2개 층 점검에 2시간이 소요되던 업무를 9개 층 점검에 3시간으로 획기적으로 단축했습니다. 이는 소요 시간 67% 감소, 업무 효율성 300% (3배) 증가에 해당하는 엄청난 성과이며, 수작업 시 발생하던 파일명 오류 등 휴먼 에러를 원천 차단했습니다.

Best Practice 3: 統合セキュリティプラットフォーム(XDR)構築・高度化

SSL可視化ソリューションによる暗号化トラフィックの復号化と、各種セキュリティアプライアンスへのミラーリング構成により、監視体制を強化しました。

課題・背景 サイバー攻撃の高度化およびトラフィックの暗号化(HTTPS)が進む中、既存のファイアウォールやIPSだけでは脅威の可視化と包括的な分析が困難になっていました。
主な取り組み
  • インターネット接続トラフィックをSSL可視化機器(SWG+SSLVA)で復号化。
  • 復号化されたミラートラフィックをAPT NXやDLPに並行して転送する高度なネットワーク設計を導入。
  • イベントを統合収集し、XDRプラットフォームに連動させるパイプラインを構築。
成果と意義 サイロ化していた各種セキュリティログを相関分析することが可能となり、脅威の早期発見とリアルタイム警報システムの確立によるインシデント対応速度の向上を実現しました。

Best Practice 3: 통합보안플랫폼(XDR) 구축 및 보안 고도화

SSL 가시성 솔루션을 통한 암호화 트래픽 복호화 및 각종 보안 시스템으로의 미러링 구성을 통해 전사적 네트워크 모니터링을 강화했습니다.

도입 배경 사이버 위협이 고도화되고 웹 트래픽의 대다수가 암호화(HTTPS)됨에 따라, 노후화된 기존 방화벽과 IPS만으로는 내부로 유입되는 악성 행위에 대한 가시성 확보와 통합 분석이 불가능했습니다.
주요 수행 내역
  • 사용자의 트래픽을 SSL 가시성 솔루션(SWG+SSLVA)을 거쳐 복호화하도록 네트워크 구성.
  • 복호화된 트래픽을 APT NX와 DLP로 동시 전송하여 탐지율 극대화 아키텍처 설계.
  • 방대한 이벤트 및 로그를 XDR 플랫폼으로 연동 및 파싱하는 데이터 파이프라인 구축.
성과 및 의의 파편화되어 있던 보안 이벤트를 XDR을 통해 통합 분석함으로써 실시간 경보 발령 및 선제적 침해 위협 대응이 가능해졌으며, 업무 효율성과 가시성이 향상되었습니다.
구성 및 흐름

Best Practice 4: 網分離環境におけるコラボレーションツール接続統制

オープンソースを活用したプロキシを構築し、高度なアクセス制御により網分離環境のセキュリティを強化しました。

課題・背景 網分離環境において特定グループウェアへのアクセスを許可しつつ、個人の私的アカウントでのログインを防ぎ、情報流出リスクを遮断する技術的制御が求められていました。
主な取り組み
  • 制御ロジック: アクセス先URLと企業ドメイン情報を含むHTTPヘッダ(AUTH等)の「AND条件」をSquid Proxyルールとして実装。
  • 既存ルールのマイグレーション、SSL証明書検証機能の適用、WebSocket通信のバイパス処理などを実施。
成果と意義 企業アカウントのみログインを許可し、個人アカウントを完全に統制する環境をソリューションメーカー初の事例として成功させ、網分離からの情報流出の抜け穴を塞ぎました。
構成・フロー

Best Practice 4: 망분리 환경 업무협업도구 개인계정 접속 통제

오픈소스 프록시를 신규 구축하고, 기업 도메인 식별 헤더를 활용한 고도화된 접근 제어를 통해 망분리 환경의 보안을 강화했습니다.

도입 배경 인터넷이 차단된 망분리 환경에서 협업도구 통신은 허용하되, 직원이 개인 계정으로 접속하여 기밀을 유출하는 행위를 차단할 기술적 통제 방안이 필수적이었습니다.
주요 수행 내역
  • 제어 로직: 목적지 URL과 기업 도메인 식별 HTTP Header(AUTH 등)의 'AND 조건'을 Squid 프록시 룰셋으로 구현.
  • SSL 인증서 검증(Trusted Root) 적용 및 WebSocket 기능 우회 방안 마련 및 테스트 수행.
성과 및 의의 오픈소스를 활용하여 개인 계정 로그인을 통제하는 환경을 제조사(솔루션 벤더) 최초 사례로 성공적으로 구축하여, 유출 사고 위험을 근본적으로 제거했습니다.

Best Practice 5: Webシェル攻撃による侵害インシデント(IR)対応

脆弱性を突いた侵入およびラテラルムーブメント(水平展開)攻撃を発見し、迅速な封じ込めから再発防止策までを主導しました。

インシデント概要 SmartEditorおよびConfluenceの脆弱性を悪用され、内部サーバーへWebシェル等がアップロードされる攻撃が発生。(分析対象: サーバー10台, PC2台)
主な取り組み
  • 検知・封じ込め: Host IPSで内部IPへの不審なスキャン行為を検知し、感染疑いのPC・サーバーを即時ネットワーク隔離。
  • 分析・強化: フォレンジックによりC2サーバーとの通信を特定。全システムのパスワード強制変更とアクセス統制強化を実施。
成果と意義 巧妙なラテラルムーブメント攻撃を初期段階で遮断し、顧客データ等の致命的な情報流出を未然に防ぐことに成功しました。

Best Practice 5: 웹쉘 공격 침해 사고 대응 (Incident Response)

알려진 취약점을 통한 시스템 침투 및 측면 이동(Lateral Movement) 공격을 조기에 발견하고, 즉각적인 격리부터 보안 강화까지 수행했습니다.

인시던트 개요 SmartEditor 및 Confluence 취약점을 악용하여, 내부 서버에 악성 웹쉘 및 파일이 다수 업로드되는 침해 사고 발생. (분석 대상: 서버 10대, PC 2대)
주요 수행 내역
  • 탐지 및 격리: Host IPS 모니터링 중 비정상 스캐닝 행위를 최초 발견, 즉각적인 주요 서버 네트워크 차단 및 격리 조치.
  • 분석 및 복구: 포렌식 분석을 통해 C2 서버 식별. 내부 개발자의 접근 통제 강화 및 전사 패스워드 일괄 변경 등 정책 재정립.
성과 및 의의 치명적일 수 있었던 내부망 침투 공격을 조기에 차단하여 실질적인 데이터 유출 피해를 완벽히 방어했습니다.

Best Practice 6: SBOMおよび脆弱性管理の自動化パイプライン構築

既存のクラウド資産管理システムにSBOMモジュールを追加開発し、脆弱性管理のライフサイクルを自動化しました。

課題・背景 新規のCVE脆弱性発生時、全サーバーへ手動でSSH接続しパッケージ情報を抽出するという、極めて非効率的な手作業プロセスが存在していました。
主な取り組み
  • Python FlaskとShell Scriptを利用し、中継サーバー経由で対象サーバーへスクリプトを自動展開・情報収集(SBOM)する機能を実装。
  • 収集したバージョン情報を分析ツールとAPI連携し、CVEの影響範囲を自動分析・業務ツールへタスクとして自動登録する仕組みを構築。
成果と意義 数百台に及ぶサーバーへの手動点検プロセスを完全に排除し、脆弱性点検の業務効率を極限まで向上させると共に、リスクの完全な可視化を実現しました。

Best Practice 6: SBOM 및 취약점 관리 자동화 파이프라인 구축

기존 클라우드 자산 관리 시스템에 소프트웨어 자산 관리(SBOM) 모듈을 추가 개발하여, 취약점 점검 자동화 파이프라인을 구축했습니다.

도입 배경 신규 CVE 발생 시, 전체 서버에 일일이 다회차 SSH 접속을 거쳐 스크립트를 실행하고 OS 패키지 버전 정보를 추출해야 하는 비효율적인 수동 점검 절차가 존재했습니다.
주요 수행 내역
  • Python Flask와 Shell Script를 활용해 중계 서버와 연동, 대상 서버에 스크립트를 자동 배포하여 소프트웨어 현황(SBOM)을 수집하도록 구현.
  • 수집 데이터를 분석 툴 API와 연동하여 CVE 영향 범위를 실시간 자동 분석하고, 취약 서버 조치 태스크를 업무 툴에 자동 등록하도록 연계.
성과 및 의의 수동 SSH 접속 과정을 완벽히 제거하여 취약점 점검 업무 효율성을 극대화했으며, 전체 서버 소프트웨어 리스크에 대한 실시간 가시성을 확보했습니다.

Best Practice 7: セキュリティエージェント自動配布システム(PMS)構築

Cortex XDRの機能と自作のインストーラー配信環境を組み合わせ、セキュリティエージェントの全社展開を自動化しました。

課題・背景 既存のエージェント配布は他部署の協力に全面的に依存しており、完了までに5ヶ月(8月〜12月)を要していました。特にMac環境は配布ツール(PMS)が存在せず、従業員による手動インストールに頼るなど大きな非効率が生じていました。
主な取り組み
  • 一般的なNginxサーバー上にインストーラーのアップロードページを構築し、専用の配布サーバーとして運用。
  • 全社PCに導入済みのCortex XDRの「Python Script実行機能」を活用し、インストーラーをダウンロードしてSilentモードで実行するPythonスクリプトを作成・展開。
成果と意義 他部署への配布作業の依存を100%排除し、セキュリティチーム単独で即時かつ統制された配布が可能になりました。Mac環境の自動配布も実現し、従来5ヶ月かかっていた作業を1ヶ月以内に完了(80%短縮)させる圧倒的な業務効率化を達成しました。

Best Practice 7: 보안 에이전트 배포 자동화 환경(PMS) 자체 구축

Cortex XDR의 스크립트 실행 기능과 자체 인스톨러 배포 서버를 결합하여 전사 엔드포인트에 대한 에이전트 배포를 전면 자동화했습니다.

도입 배경 기존 보안 에이전트 배포는 타 부서의 협조에 전적으로 의존해야 했으며, 전체 배포에 5개월(8~12월)이 소요되었습니다. 특히 Mac 환경은 PMS가 부재하여 임직원이 직접 설치해야 하는 심각한 비효율이 존재했습니다.
주요 수행 내역
  • 일반 Nginx 웹 서버에 에이전트 인스톨러 업로드 페이지 및 배포 환경(PMS)을 자체 구축.
  • 전사 PC에 기 설치된 Cortex XDR의 'Python Script 실행 기능'을 활용, 업로드된 인스톨러를 엔드포인트에서 다운로드 및 Silent 모드로 자동 설치하는 파이썬 스크립트를 작성하여 일괄 적용.
성과 및 의의 타 부서 의존성을 100% 제거하고 보안팀 자체적으로 주도적인 배포 및 통제가 가능해졌습니다. Mac 환경의 자동 배포를 실현하였으며, 하루 30대씩만 진행하더라도 기존 5개월이 걸리던 배포를 1개월 이내로 80% 단축하는 압도적인 업무 효율성을 달성했습니다.
구성 및 흐름
